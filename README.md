# dsh-role-play-story

多角色故事模式，是 [dsh-role-play](../dsh-role-play) 的**子插件**。

让几个角色进入同一个场景：他们会和你说话，也会**互相说话**——接话、反驳、争抢、冷战。界面与主插件保持一致。

> **需要先安装并启用 [dsh-role-play](https://github.com/zhengwuyu957/dsh-role-play)**，本插件从那里读取角色卡和模型配置。缺失时会显示提示页，不会崩溃。

## 玩法

**角色与你互动，角色之间也互动**

每轮模型会决定「谁开口、说什么」，输出 2～4 段，按角色分段展示。角色知道彼此在场，会引用对方刚说的话，产生立场冲突、吃醋、旧怨或默契。

**两种节奏**
- **轮流**：按顺序让角色依次开口，秩序感强，适合正经推进剧情
- **自由**：谁情绪最强谁先说，可以有打断、抢话的混乱感，更适合冲突戏

**自动续演**
打开后每轮结束自动让故事往下走，想看他们自己演下去时很方便，随时可以叫停。

## 新建故事

左侧栏「+ 新建故事」提供两条路径：

- **手动创建**：自己写标题、背景，从现有角色卡里挑 2～4 个出场
- **情节生成**：描述你想要的情节（如「三个人被困在停电的公寓，旧情敌突然出现」），AI 会一次性产出**故事标题、故事背景、开场白和 2～4 张角色卡**

## 开场白

新建的故事不会是一片空白——AI 会同时写一段开场白，让戏直接开演：

- 用 3～5 段角色发言开场，制造一个正在发生的小冲突或暧昧瞬间
- 结尾留出空档，让你马上有话说
- **不会写你扮演的那个角色**，那部分留给你

手动创建的故事也可以在编辑器里点「**生成开场白**」，按当前的标题、背景和阵容现写一段，可以反复重生成或清空。

## 情节生成会从零建卡

生成出来的角色卡会**直接写进「角色扮演」插件的角色列表**，并自动选进这个故事：

- 角色**全部是 AI 原创**的，不使用你已有的角色卡（只在起名时避开重名）
- 新角色的「情景」字段会填入这个故事背景，所以单独打开他聊天时也有上下文
- 生成后进入编辑器，标题、背景、出场角色都能改；角色的详细设定去主插件里改
- 你可以反复生成，不满意的角色删掉即可

这意味着**即使一张角色卡都没有，也能直接从「新建故事」开始**。

## 你在这个故事里的位置

AI 生成情节时会**指定一个角色由你来演**，其余角色由 AI 扮演：

- 编辑器里的「**你扮演谁**」可以随时改，也能切到「玩家旁观」（全员由 AI 演）
- 你发的每句话，都会算作你扮演的那个角色说的话，气泡上显示他的名字
- AI **不会替你演**：它不会写你的台词、动作和心理活动，只会写其他角色对你的反应
- 角色们知道你在场，会看着你、跟你说话、对你有情绪，每轮结尾都会留话让你接

这样故事是「你和他们的」，而不是「AI 演一群人、你在旁边看」。

## 界面

和主插件一致：左侧故事列表，右侧聊天流。

- 每条角色消息带对应角色的头像与名字
- 括号内的动作描写显示为灰色
- 鼠标悬停消息出现 **↩**，可回溯到那一轮
- 故事列表显示每个故事的角色数量

## 安装

需要先装好 `dsh-role-play`。

```sh
git clone https://github.com/<your-name>/dsh-role-play-story.git
```

然后在 DSH 里用 Plugin Manager 安装这个目录：

```js
pluginManager.install_bundle({ action: 'install_bundle', target: '<仓库绝对路径>' })
```

装完 **完全退出 DSH 再打开**，进入任意会话，视图栏会多出「**多角色故事**」。

### Windows 跨盘符注意

若仓库与 profile 不在同一个盘，pnpm 生成的符号链接可能失效。把链接换成 junction：

```powershell
$link = "$env:DSH_PROFILE_DIR\node_modules\dsh-role-play-story"
(Get-Item $link).Delete()
New-Item -ItemType Junction -Path $link -Value "<仓库绝对路径>"
```

## 工作原理

主插件通过两条通道暴露共享接口（`roleplayChat`）：

```
getCharacters()        读取全部角色卡
getCharacter(id)       读取单个角色
getModel()             当前模型
complete(...)          复用主插件的模型调用
onChange(fn)           订阅角色卡变化
createCharacter(card)  新增一张角色卡（情节生成自动建卡用）
```

本插件的 Client 半部通过 `window.__DSH_ROLEPLAY_HUB__` 或 Cordis 服务 `ctx.get('roleplayChat')` 获取，取不到时会轮询等待——所以主插件加载得晚也没关系。

Host 半部是空的：所有模型调用都复用主插件的 `/rp-chat/api/*` 路由。

## 数据存放

所有数据都存在浏览器 `localStorage`，插件本身**不写任何文件、不碰你的硬盘**。键名前缀 `rpStory.`。

| 键 | 存什么 |
|---|---|
| `rpStory.stories.v1` | 每个故事的标题、背景、出场角色、你扮演的角色，以及完整对话记录 |
| `rpStory.selected.v1`、`rpStory.mode.v1`、`rpStory.auto.v1` | 当前故事、轮流／自由节奏、自动续演开关 |

注意两点：

- **故事里没有独立的「记忆」机制**。多角色同场的上下文就是完整对话记录本身，聊得越久上下文越长，不会自动压缩。
- **角色卡仍由主插件管理**，包括自动生成的那些。它们在「角色扮演」的 `rpChat.characters.v1` 里，删掉那边，这边的故事会找不到角色。

清除浏览器数据或换浏览器，这些都会消失。

## 已知限制

- 依赖主插件，不能单独使用
- 多角色同场时上下文更长，长故事会比单角色更快触及上下文上限
- 角色分段依赖模型遵守 `[[角色名]]` 标记协议，偶尔可能串段
- 界面文案固定中文
